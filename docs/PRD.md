# PRD — Heliostat: навчальна двовісна система наведення

**Курс:** Системне програмування вбудованих систем  
**Лабораторна робота:** №1  
**Форма:** B — Wokwi + STM32 HAL, C  
**Платформа:** NUCLEO-C031C6 (STM32C031C6)  
**Стан:** працездатний прототип керування двома осями; реальне стеження за сонцем — заплановане розширення.

## A. Загальна ідея

Проєкт імітує двовісну систему наведення сонячної панелі. Контролер STM32C031C6 приймає два аналогові сигнали, розраховує відповідні кути та генерує PWM для двох сервоприводів. Користувач може переходити між режимами `AUTO` (оновлення положень за входами ADC) та `STANDBY` (утримання попереднього положення). Через UART відображається поточний стан.

У Wokwi потенціометри замінюють реальні фотодатчики. Отже, поточний `AUTO` означає **автоматичне виконання заданих аналоговими входами позицій**, а не пошук максимального реального освітлення. Пізніша версія могла б використовувати чотири фоторезистори та алгоритм визначення напрямку на джерело світла.

## B. Функціональні вимоги

| ID | Вимога | Стан після ЛР1 |
|---|---|---|
| FR-01 | Після запуску система повинна вивести назву й стан ініціалізації через USART2. | Реалізовано |
| FR-02 | Система повинна зчитувати два аналогові входи ADC1 з 12-бітною роздільністю. | Реалізовано, перевірено |
| FR-03 | Система повинна перетворювати значення ADC 0–4095 у цільові кути 0–180°. | Реалізовано, перевірено за UART |
| FR-04 | Система повинна формувати два PWM-сигнали 50 Гц із керувальними імпульсами 1–2 мс. | Реалізовано; виміряно один приклад імпульсу |
| FR-05 | У режимі AUTO система повинна оновлювати положення двох сервоприводів відповідно до аналогових входів. | Реалізовано, перевірено у Wokwi |
| FR-06 | У режимі STANDBY система повинна зберігати останні положення сервоприводів, продовжуючи зчитування ADC. | Реалізовано, перевірено у Wokwi |
| FR-07 | Натискання кнопки MODE повинно перемикати AUTO ↔ STANDBY з придушенням дребезгу. | Перемикання працює; антидребезг потребує вдосконалення |
| FR-08 | Система повинна перевіряти присутність OLED SSD1306 за I²C-адресою 0x3C та повідомляти результат в UART. | Реалізовано (`OLED: FOUND`) |
| FR-09 | Система повинна виводити не рідше одного разу на секунду значення ADC, розраховані кути та режим. | Реалізовано, перевірено |
| FR-10 | Прошивка повинна збиратися відтворювано в Docker командою `make build` і запускатися в Wokwi. | Реалізовано, перевірено |
| FR-11 | OLED повинен відображати поточні кути й режим системи. | Заплановано, ще не реалізовано |
| FR-12 | Майбутня версія повинна визначати напрямок максимальної освітленості за чотирма фоторезисторами. | Заплановано, ще не реалізовано |

## C. Компоненти та обґрунтування

| Компонент | Інтерфейс | Пов'язані FR | Навіщо; альтернативи |
|---|---|---|---|
| Два потенціометри Wokwi | ADC (PA0, PA1) | FR-02, FR-03, FR-05 | Імітують два керувальні аналогові сигнали. Реальні GM5528 не потрібні для початкового Wokwi-прототипу. |
| Два Wokwi servo | PWM TIM3 (PB4, PB5) | FR-04–FR-06 | Поворот макета по двох осях. Крокові двигуни складніші у керуванні. |
| Кнопка Wokwi | GPIO Input Pull-up (PA8) | FR-06, FR-07 | Перемикання режиму. UART-команда вимагала б парсера команд. |
| OLED SSD1306 | I²C (PB8/PB9), адреса 0x3C | FR-08, FR-11 | Перевірка I²C, майбутня індикація. LCD1602 — альтернатива. |
| Serial Monitor | USART2 (PA2/PA3) | FR-01, FR-09 | Діагностика й журнал без окремого фізичного дисплея. |
| Logic Analyzer Wokwi | D0–D3 | FR-04, FR-08 | Верифікація PWM та I²C. Альтернатива — фізичний логічний аналізатор для форми A. |

Модель включає компоненти з інтерфейсами ADC, GPIO, I²C, PWM та UART. Дисплей і сервоприводи не називаються сенсорами; для форми B використано дозволений методичкою набір компонентів з різними інтерфейсами.

## E. Обмеження та подальші роботи

1. Wokwi-модель не містить сонячної панелі або реальних фотодатчиків; це навчальна перевірка двовісного керування.
2. Поточні `angleX`/`angleY` у UART — **обчислені цільові кути**, а не виміряний зворотним зв'язком стан механізму.
3. Виведення інформації на OLED поки не реалізоване, хоча його I²C-адреса відповідає.
4. Потрібно покращити антидребезг кнопки та за потреби записати окремий тест із багаторазовими натисканнями.
5. Наступний етап: підтримка чотирьох LDR, порівняння освітленості, обмеження кутів і руху, налаштування гістерезису, OLED-відображення.
